# Accessibility Coverage Matrix — Milestone 10.10B1

**Method note (read before using this table):** This matrix was produced entirely by a static, offline read of the source code. No browser, no automated scanner (axe/Lighthouse/Playwright), and no real screen reader (NVDA/VoiceOver/JAWS) were run against a live instance of the app in this pass. Every cell in the "Automated scan," "Keyboard," "Zoom," and "Mobile" columns is honestly marked **Not tested (static-read only, no browser available)** — nothing here should be read as evidence those dimensions pass or fail. "Findings" summarizes only what could be determined by reading JSX/TSX source: DOM structure, ARIA attributes, class names, and component composition. Anything that depends on runtime behavior (actual focus movement, actual screen-reader output, actual rendered contrast, actual viewport reflow, actual Base UI dialog focus-trap behavior) is called out as unverified even where the code strongly suggests it works.

This supersedes an earlier draft of this file from an earlier pass in this same docs folder — several routes that draft marked "not deep-read this pass" (onboarding, `/confirm/[token]`, `/verify/[token]`, `/review/[token]`) were read in full for this version, and additional defects were found there (see accessibility-defects.md).

**Live-repo note:** while this static audit was in progress, a concurrent process modified 6 source files, applying fixes for several of the defects found here (skip link, `<main id="main-content">` on `AuthShell`, a page-level `<h1>` on `/portfolio/new`, and a dangling `aria-describedby` fix on the file-upload form). This table and accessibility-defects.md were re-checked against `git diff` and updated to say so explicitly at each affected row — look for **"Fixed during this audit"** below. This task did not make or revert any of those source edits.

## Explicit gaps in this pass

- No real browser session, so zoom (200%/400%) and 320px reflow were **not tested** for any route.
- No automated scanner was run.
- Color contrast was not computed against the OKLCH theme tokens in `src/app/globals.css` — no obviously low-contrast pair was spotted in a fast read, but this is not a substitute for a computed contrast-ratio check and is **not** claimed as passing.
- `/saved`, `/applications`, `/applications/[id]`, `/reminders`, `/portfolio/review`, `/portfolio/review-links`, `/settings`, `/profile` were checked for headings/landmarks/live-regions via targeted grep, not a full line-by-line read of every form control and interactive element on those pages — a deeper pass could surface additional field-level issues of the kind found on `/onboarding`.
- Base UI's `Dialog` focus-trap/Escape/restoration behavior is inferred from the library's documented contract, not observed at runtime.
